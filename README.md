# CS2 Stats Bot

Telegram-бот, который после матча в **Counter-Strike 2** присылает игроку разбор игры:

- **статистика:** K/D, ADR, KAST, HS%, MVP, мультикиллы, K/D за CT и за T, упрощённый рейтинг;
- **разбивка по раундам:** сторона, результат, фраги, хедшоты, ассисты, урон, секунда смерти, деньги;
- **разбор ошибок:** позиционка, тайминги, урон, экономика, гранаты (с номерами раундов);
- **3 конкретных совета** на следующую игру.

Данные приходят в реальном времени через **Game State Integration** (HTTP, порт `30000`).
Матч можно также импортировать из **лога консоли** (`condump`) или из записи GSI.

```
🎮 Mirage — Поражение 0:16
📊 Статистика
K / D / A: 6 / 16 / 0   K/D: 0.38
ADR: 60.0   KAST: 37.5%   HS: 0.0%
🔍 Разбор ошибок
• Позиционка: 10 раз(а) погиб в первые 20 сек раунда без фрага … (раунды 2, 3, 5 …)
• Экономика: В 3 раундах при деньгах ≥$5000 играл без полной закупки. (раунды 5, 6, 7)
🎯 3 совета на следующую игру
1. …
```

## Как это работает

```
CS2 (игрок) ──HTTP POST JSON──▶ :30000  GSI-сервер ──▶ трекер матча ──▶ SQLite
                                                              │
Telegram ◀──webhook (HTTPS, nginx)──▶ :8080 aiogram 3 ◀──────┘  отчёт после gameover
```

1. Пользователь пишет боту `/start` и получает файл `gamestate_integration_cs2statsbot.cfg`
   с личным токеном.
2. Кладёт его в `…\Counter-Strike Global Offensive\game\csgo\cfg` и перезапускает CS2.
3. CS2 сам шлёт состояние игры на сервер. Бот по токену понимает, чей это матч,
   собирает статистику по раундам и после окончания матча сам присылает отчёт.

### Команды

| Команда | Что делает |
|---|---|
| `/start` | приветствие и cfg-файл |
| `/stat [id]` | отчёт по последнему (или указанному) матчу |
| `/rounds [id]` | разбивка по раундам |
| `/history` | 10 последних матчей |
| `/export [id]` | матч в JSON |
| `/cfg` | cfg-файл ещё раз |
| `/newtoken` | сменить токен |
| документ | импорт: лог консоли (`condump`), JSON/JSONL с GSI, экспорт бота |

## Структура

```
core/                 логика без зависимостей (тестируется отдельно)
  gsi.py              трекер потока GSI → раунды и матч
  stats.py            K/D, ADR, KAST, HS%, MVP, рейтинг
  analysis.py         разбор ошибок и советы
  console_import.py   импорт из condump / JSON / JSONL
  report.py           тексты отчётов для Telegram
bot/
  main.py             запуск: webhook или polling + GSI-сервер
  gsi_server.py       aiohttp-сервер на :30000
  handlers.py         команды aiogram 3
  storage.py          SQLite
deploy/               nginx, systemd
tests/                unittest + симулятор матча
tools/demo.py         демо-отчёт и отправка тестового матча на сервер
```

## Запуск локально (polling)

```bash
python -m venv .venv && . .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env        # впиши BOT_TOKEN, WEBHOOK_BASE_URL оставь пустым
                            # GSI_PUBLIC_URL=http://127.0.0.1:30000/  — если CS2 на этом же ПК
python -m bot.main
```

Проверить без игры:

```bash
python -m tools.demo                                       # отчёт в консоль
python -m tools.demo --send http://127.0.0.1:30000/ ТОКЕН  # токен — из cfg, который прислал бот
```

## Деплой на сервер (Docker + webhook)

1. VPS с публичным IP и доменом, указывающим на него.
2. `cp .env.example .env`, заполнить:
   - `BOT_TOKEN`;
   - `WEBHOOK_BASE_URL=https://bot.example.com`, `WEBHOOK_SECRET` — случайная строка;
   - `GSI_PUBLIC_URL=http://<IP или домен>:30000/`.
3. `docker compose up -d --build`
4. nginx + HTTPS для вебхука: `deploy/nginx.conf`, затем `sudo certbot --nginx -d bot.example.com`.
5. Открыть порт: `sudo ufw allow 30000/tcp` (и 443).

Без Docker — `deploy/cs2-stats-bot.service` (systemd).

> CS2 отправляет GSI обычным HTTP, поэтому порт 30000 открыт напрямую. Чужие данные
> не примутся: каждый запрос проверяется по личному токену из cfg (иначе `403`).

## Тесты

```bash
python -m unittest discover -s tests -t .
```

Тесты прогоняют смоделированные матчи через тот же трекер, что и живой GSI:
подсчёт раундов, смертей, MVP, денег, все категории ошибок, импорт из консоли и JSON,
длину сообщений (< 4096 символов).

## Ограничения GSI

CS2 отдаёт игроку только данные о нём самом: без координат и без информации о соперниках
(полные данные — только у наблюдателя/GOTV). Поэтому:

- позиционка и тайминги оцениваются по косвенным признакам: секунда смерти, урон до смерти,
  ослепление, неиспользованные гранаты, смерти за CT и за T;
- в KAST не учитываются размены (Trade);
- при импорте из консоли нет денег и таймингов: фраг = ≥100 урона по игроку, смерть = ≥100 полученного.

Для точного разбора позиций можно добавить парсинг демо (`.dem`) — следующий этап.
